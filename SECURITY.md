## Reporting a Vulnerability

The MoreOps team takes security issues seriously. If you discover a security vulnerability, please do NOT create a public issue on GitHub.

Instead, please report the vulnerability privately via:
- **Email**: arthasblackmore@gmail.com
- **GitHub Security Advisory**: Use the "Report a vulnerability" tab on GitHub.

### What to include in your report:
1. Description of the vulnerability.
2. Steps to reproduce the issue (proof of concept, configuration, or CLI command).
3. The potential impact of the issue.
4. Any proposed fixes or mitigations.

You will receive an acknowledgment of your report within 48 hours, along with an estimated timeline for a fix.

## Secure by Default Principles in MoreOps

MoreOps enforces security at every stage:
- **Pod Security Standards**: Pods run as non-root (`UID 10001`), with `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, and `capabilities: drop: [ALL]`.
- **Zero Hardcoded Secrets**: Secrets are managed via HashiCorp Vault and External Secrets Operator (ESO).
- **Service Account Hardening**: Tokens are not auto-mounted (`automountServiceAccountToken: false`).
- **Network Isolation**: Strict `NetworkPolicy` generated by default.
- **Built-in Static Linter**: `moreops validate` automatically flags insecure Pod and Service specifications.
